---
title: "Adaptive surfaces"
description: "Liquid Glass where the system provides it, with native fallbacks chosen by role."
---

Describe what a surface is for. swiftcn chooses the best native appearance for the running system.
Availability checks stay inside the library, so your views contain no `#available` branches.

```swift title="AdaptiveSurfacesExample.swift"
import SwiftUI
import SwiftCN

struct AdaptiveSurfacesExample: View {
    @State private var expanded = false
    @Namespace private var surfaces

    var body: some View {
        VStack(spacing: 16) {
            Button("Continue") {}
                .buttonStyle(.tw("glass-prominent px-4 font-semibold"))
            TWSurfaceGroup(spacing: 12) {
                HStack(spacing: 12) {
                    Button("Tools") { withAnimation(.smooth) { expanded.toggle() } }
                        .buttonStyle(.plain)
                        .tw("px-4 py-2 surface-floating glass-interactive")
                        .twSurfaceID("tools", in: surfaces)
                    if expanded {
                        Text("Draw").tw("px-4 py-2 surface-floating")
                            .twSurfaceID("draw", in: surfaces)
                    }
                }
            }
            Text("Settings").tw("p-4 surface-solid rounded-lg")
        }
        .twAppearance(.automatic)
        .twGlassRenderer(.automatic)
    }
}
```

## Surface roles

| Class | Liquid Glass systems | Earlier systems | Reduce Transparency |
| --- | --- | --- | --- |
| `surface-floating` | Liquid Glass | Regular material with a themed edge | Themed solid surface |
| `glass` | Liquid Glass | Regular material with a themed edge | Themed solid surface |
| `surface-solid` | Themed solid surface | Themed solid surface | Themed solid surface |

Liquid Glass systems are iOS 26 and macOS 26 and later.
Native glass adapts to Reduce Transparency and Increase Contrast itself, so swiftcn keeps it.
The material fallback becomes solid under Reduce Transparency. Increase Contrast strengthens the fallback edge.

Every surface resolves to exactly one fill. `bg-*` selects the color of a solid surface; it never stacks under glass or a material.
Explicit `border-*` classes replace the fallback edge, and `rounded-*` replaces the default capsule shape.
Shadows apply to solid and material fills. Glass supplies its own depth.

Variants work with the same conflict rules as other classes:

- `glass-interactive` turns on Apple's touch and pointer feedback for the glass. It installs no gesture.
- `glass-tint-primary`, or any theme color, tints the glass. `glass-tint-[\(color)]` accepts a native `Color`.
- `glass-prominent` selects the prominent native button style. On other views it draws as `glass`.

## Appearance policy

The theme keeps colors, spacing, type, and radii. `.twAppearance` decides how floating surfaces look:

| Policy | `surface-floating` | Native sheets with `twPresentationSurface()` |
| --- | --- | --- |
| `.automatic` (default) | Glass where the system draws glass | System sheet where the system draws glass; themed surface otherwise |
| `.glass` | Glass whenever available | System sheet whenever glass is available |
| `.solid` | Themed solid surface | Themed surface |

Local classes override the policy: `glass` stays glass under `.solid`, and `surface-solid` stays solid under `.glass`.
Global defaults from `TWGlobalRules.view` are overridden by local classes in the usual way.

If your app sets `UIDesignRequiresCompatibility` in its Info.plist, `.automatic` follows it and uses the earlier appearance.
Use `.twAppearance(.glass)` or the `glass` class to opt specific surfaces back in.

## Glass renderer

`.twGlassRenderer` chooses the framework that draws glass surfaces and groups. Fills, roles, and the appearance policy stay the same.

| Renderer | iOS 27 and later | iOS 26 | macOS 26 and later |
| --- | --- | --- | --- |
| `.automatic` (default) | UIKit | SwiftUI | SwiftUI |
| `.swiftUI` | SwiftUI | SwiftUI | SwiftUI |
| `.uiKit` | UIKit | UIKit | SwiftUI |

On a physical iPhone running iOS 27.0.1, SwiftUI's `glassEffect` anywhere in a window stopped the window redrawing, while state and touches kept working.
UIKit's `UIGlassEffect` renders correctly, so `.automatic` uses it on iOS 27 and later. The iOS simulators never showed the problem.
Use `.twGlassRenderer(.swiftUI)` to return to SwiftUI's glass once the system is fixed.

UIKit's renderer draws a `UIVisualEffectView` with `UIGlassEffect` behind each glass surface, using the surface's tint, `glass-interactive`, and corner shape.
It never applies SwiftUI's `glassEffect`, not even `.identity`. Solid and material fills, including the Reduce Transparency fallback, create no glass view at all.
The glass view only draws: SwiftUI keeps every touch, so `glass-interactive` may not show UIKit's touch response.

The renderer depends only on the system and this setting, never on accessibility, so it selects a view structure once.
Set it near the root of your app and leave it: changing it rebuilds the surfaces below.

Glass buttons follow the renderer too. With UIKit's renderer, `glass` and `glass-prominent` buttons never use SwiftUI's `.glass` or `.glassProminent` styles:

- A plain `Button` keeps its role, action, and accessibility. A UIKit glass view is drawn behind its label, at the native styles' sizes: 28 points tall for `control-sm` and `control-mini`, 34 for the regular size, and 50 for `control-lg` and `control-xl`. On iOS the touch target is at least 44 points, without changing layout.
- `glass-prominent` tints the glass with the `tint-*` color, or the inherited tint, and keeps the white label. Plain `glass` stays clear with the primary label, unless a `tint-*` class tints it.
- Buttons are capsules unless a `rounded-*` class sets corners.
- Pressing scales the button to 96% and fades it to 78% with a spring. Reduce Motion keeps the fade with a short ease-out and no scale.
- Disabled buttons drop the tint and use the system's disabled label color.
- Under Reduce Transparency a themed solid fill replaces the glass view: the surface color with its edge for `glass`, the tint for `glass-prominent`. Only the background changes, so the button keeps its identity.
- Glass buttons draw their own glass and do not blend with a `TWSurfaceGroup`.

Controls the system draws itself, such as sheets, menus, pickers, and toolbars, keep the system appearance.

## Native buttons

Every `.buttonStyle(.tw(...))` button whose classes choose a native style is drawn by Apple.
On a button, `glass` and `glass-prominent` select `.glass` or `.glassProminent` on Liquid Glass systems, and `.bordered` or `.borderedProminent` otherwise. With UIKit's renderer they draw UIKit's glass instead; see [Glass renderer](#glass-renderer).
`surface-solid` always selects the bordered styles.
Classes add spacing and typography to the label. Background, border, and shadow classes are ignored so nothing paints over the native control.
Use `tint-*` or the native `.tint` modifier for color.

Accessibility settings never change the selected style type, so a button keeps its identity, focus, and pending activation.

## Groups and morphing

`TWSurfaceGroup` wraps `GlassEffectContainer`, so nearby glass shapes blend and morph together.
`twSurfaceID(_:in:)` wraps `glassEffectID`. Apply it after the surface's `.tw` classes.
Earlier systems show the content unchanged and ignore the identifier. Use native transitions for those.

With UIKit's renderer, `TWSurfaceGroup` draws its surfaces' glass in one `UIGlassContainerEffect` behind its content, so nearby shapes still blend.
Each surface reports its bounds to the group. Glass that arrives materializes, glass that leaves dematerializes, and glass that moves follows the transaction's animation.
`twSurfaceID(_:in:)` names a surface's glass shape: a surface that leaves and one that arrives with the same identifier share one shape, which moves and resizes between them.
This differs from SwiftUI's container in a few ways:

- The group's glass sits behind all of the group's content, not behind each surface. Avoid overlapping a grouped surface with other content in the group.
- Glass follows the surfaces' layout and the transaction's animation. Render-time effects such as `scaleEffect`, and scroll offsets inside the group, may not move it, so keep scroll views and scaled surfaces outside the group.
- A surface in a sheet or popover presented from inside the group draws its own glass.

## Native sheets

Apply `twPresentationSurface()` at the root of a sheet. It keeps the system sheet where the system draws glass, and applies the theme's `surface` color otherwise.
Inside such a sheet, `twSystemPresentation` is true and `CNDrawerContent` omits its recipe fill. `CNDrawer` applies this for you.
Native toolbars, navigation bars, and tab bars already use the system appearance; swiftcn does not restyle them.

## Stable content

Policy, system, and accessibility changes alter values inside a fixed view structure.
Editors keep their text, bindings, and focus when Reduce Transparency, Increase Contrast, or the policy changes.

Keep a view's surface role constant.
Switching a view between a surface class and no surface class rebuilds its content.
Switch between `surface-floating`, `glass`, and `surface-solid` instead, or change the policy.

## Interaction stays explicit

Surface classes describe appearance only.
`.tw` never installs gestures, and Automatic never changes a component's interaction model between system versions.
Custom drag, sheet-versus-swipe arbitration, scroll handoff, and keyboard clearance stay in component interaction code.

## Toolchain

Build with Xcode 26 or later. The package keeps its iOS 17 and macOS 14 deployment targets and checks availability at run time.
